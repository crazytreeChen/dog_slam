# 离线雷达建图与定位匹配算法——当前未完成事项与进展归档

## 1. 任务背景与目标
- **核心任务**：编写一个完全脱离 ROS 环境依赖的离线 Python 脚本，读取多帧激光雷达数据（来自 `.npz`）并在已有的占据栅格地图上进行全局匹配，估计出 `odom -> map` 的位姿变换（平移 + 旋转 Yaw）。
- **输入数据**：`ros2/src/auto_initial_pose_calibrator/scan_viz/debug_match_data.npz`
- **关键约束**：不能使用 `tf_odom_to_map` 作为搜索的初始值（这是要解的未知量），同时必须解决 **180° 的航向角消歧（镜像匹配）** 问题。
- **输出**：生成可视化图像展示对齐效果，并输出最终的坐标变换。

---

## 2. 当前最新进展
- **已完成的工作**：
  - 重构并优化了 `calculate_and_visualize_lidar_positions.py` 脚本，实现了全地图多分辨率网格搜索：
    - **Phase 1 (粗搜)**：全地图范围，2.0m 步长，15° 航向角步长，基于降采样点云。通过非极大值抑制（NMS）筛选出前 5 个最可能的候选位置。
    - **Phase 2 (中搜)**：在候选位置周围（±3.0m, ±20°），以 0.5m 步长、5° 航向角步长进行局部搜索，得到前 8 个精化候选。
    - **Phase 2.5 (180° 消歧)**：对 Top 候选解进行独立单帧投影评分及轨迹空闲空间检查，试图打破 180° 镜像对称性。
    - **Phase 3 (精搜)**：对消歧后的优胜者在小范围内（±0.6m, ±6°）以 0.05m、0.5° 进行超精细搜索。
    - **可视化**：生成 4 视图图像展示合并形状、地图、匹配叠加效果及还原的轨迹。
- **代码中已加入诊断逻辑**：在 Phase 1 之后加入了 `[DIAG] GT score` 诊断代码，会使用 Ground Truth 真实位姿进行评分，分别计算其在粗搜点云和全量点云下的得分，用以和搜索出来的错误镜像解进行量化对比。

## 3. 当前未完成的问题与瓶颈（阻碍项）

### 3.1. 180° 航向角消歧失效（关键问题）
- **现象**：算法在执行中最终定位在 `Yaw ≈ 44.5°`，而真值为 `Yaw ≈ -136.3°`（两者几乎正相反，相差约 180°）。
- **原因分析**：
  1. 雷达的多帧融合点云在旋转 180° 后，与地图的轮廓仍具有极高的几何对称性。
  2. 尝试过的消歧方法（如：轨迹在地图上的空闲区域比例、已知区域比例、单帧独立评分均值）均无法有效拉开分差。在本数据集中，镜像 45° 位姿下的轨迹刚好也全部落在空旷区域内，且单帧评分甚至略高于真实 -136.3° 位姿。
- **痛点**：目前尚不知道 Ground Truth 位姿在距离场地图中的实际得分。如果在粗搜阶段真实位姿的得分就已经很低，那么它根本无法进入 Phase 2/2.5，导致消歧机制巧妇难为无米之炊。

### 3.2. 诊断代码尚未成功运行
- **现象**：由于本地 Conda 环境配置及命令行执行路径的间歇性报错，新版带有 `[DIAG]` 诊断输出的代码尚未跑通，无法观察到真值的得分表现。
- **急需解决**：需要修复 Conda 环境调用方式，跑通新脚本并获取控制台日志。

## 4. 下一步解决思路与实施方案

### 步骤一：跑通 GT 诊断，定位根源
1. 解决 Windows 环境下 conda 或 python 的执行环境问题。
2. 运行带有 GT 诊断输出的 `calculate_and_visualize_lidar_positions.py`，记录：
   - GT 位姿的 Phase 1 评分。
   - GT 位姿的 All pts 评分。
   - Phase 1 搜索出的 Top 5 候选解中，是否有包含真实 -136.3° 附近的候选。
3. **根据诊断结果分类讨论**：
   - **情况 A (粗搜遗漏)**：GT 的 All pts 评分很高，但 Phase 1 评分低或未进前五。说明 2m 的粗搜网格步长太大，把真值漏掉了。
     * *对策*：降低 Phase 1 的搜索步长（如 1.0m 或 1.5m，角度 10°），或者增大 NMS 提取的候选池数量（如保留 Top 10 或 Top 15）。
   - **情况 B (评分函数缺陷/对称性极强)**：GT 的 All pts 评分确实显著低于错误镜像解。说明单纯用点到墙壁的距离场（Distance Field）不足以区分正反。
     * *对策*：必须引入能够感知“空无/被阻挡”特征的评估方法（例如光线投射）。

### 步骤二：引入“光线投射模拟（Ray-casting Sim）”进行消歧
如果确定是情况 B，可采用**雷达射线模拟投射**来彻底破除 180° 镜像模糊：
- **原理**：雷达数据不仅告诉我们“哪里有墙（点云）”，还隐含地告诉我们“从雷达原点到墙之间是空旷的（Free space）”。
- **实现方案**：
  1. 对进入消歧阶段的 Top 候选位姿，在地图中对每一帧的雷达原点进行多方向的“射线投射（Ray-casting）”。
  2. 根据栅格地图计算射线的“理论测量值”（即射线碰到地图墙壁的距离）。
  3. 将理论测量值与该帧雷达的实际测距值（ranges）进行比对（如计算平均绝对误差 MAE）。
  4. **消歧效果**：在正确方向上，实测的雷达射线击中墙壁的距离与地图射线完全相符；而在 180° 镜像位置，原本朝向空旷走廊的雷达射线在投影后会“穿过地图墙壁”，而原本朝向墙壁的射线在投影后会在空旷区域“凭空截止”，从而产生极大的测距偏差，使分差极其显著。

### 步骤三：利用轨迹延伸方向进行碰撞检查
- **原理**：机器人运动的轨迹在地图中通常应位于通道中央。
- 如果将 odom 轨迹旋转 180° 投影到地图，虽然点云可能刚好和墙壁重合，但整个轨迹的移动路径可能会穿过某些墙体或障碍物。
- 可对整条轨迹进行更密集的碰撞检测，而不仅仅是检查雷达帧原点。
